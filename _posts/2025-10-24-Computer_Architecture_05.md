## 1. 부호 확장 (Sign Extension)

MIPS I 형식 명령어의 상수(immediate)는 **16비트**인데 레지스터와 ALU는 **32비트**다. 16비트 값을 32비트로 늘릴 때 **부호 비트(맨 왼쪽 비트)를 상위 16비트에 복사**하는 것이 부호 확장이다.

| 16비트 값 | 0으로 채우면 | 부호 확장하면 |
| --- | --- | --- |
| `0000 0000 0000 0101` (+5) | +5 | +5 |
| `1111 1111 1111 1011` (−5) | +65,531 | −5 |

- **왜 필요한가**: `addi $t0, $t0, -5`, `lw $t0, -4($sp)`, `beq`의 뒤쪽 분기처럼 **음수 상수**가 자주 쓰이는데, 0으로 채우면 값이 완전히 달라진다
- 예외: `andi`, `ori`, `xori` 같은 **논리 연산**은 비트 패턴을 그대로 쓰기 위해 0으로 채운다(zero extension)

## 2. 주소 지정 방식

| 방식 | 피연산자 위치 | 예 |
| --- | --- | --- |
| 즉시(immediate) | 명령어 안의 상수 | `addi $t0, $t0, 4` |
| 레지스터 | 레지스터 | `add $t0, $t1, $t2`, `jr $ra` |
| 베이스(변위) | 레지스터 + 상수 주소 | `lw $t0, 8($s0)` |
| **PC 상대** | (PC + 4) + 상수 × 4 | `beq`, `bne` |
| **의사 직접** | PC 상위 4비트 + 26비트 주소 + 00 | `j`, `jal` |

### PC 상대 주소 지정 (PC-relative addressing)

분기 목표 주소를 **다음 명령어 주소(PC + 4)를 기준으로 한 거리**로 표현한다.

$$\text{target} = (PC + 4) + \text{signext}(\text{offset}) \times 4$$

- 오프셋은 16비트 부호 있는 수이고 단위가 **명령어(4바이트)** 라서 × 4를 한다
- 분기는 대부분 가까운 곳(반복문, if)으로 가기 때문에 ±2^15개 명령어 범위면 충분하다
- 예: PC = 80, offset = 2이면 target = 84 + 8 = 92

### 의사 직접 주소 지정 (Pseudo-direct addressing)

`j`, `jal`은 26비트 주소 필드를 가진 J 형식이다. 32비트 주소를 만들려고

$$\text{target} = (PC + 4)[31:28] \;\Vert\; \text{address}_{26} \;\Vert\; 00$$

- 하위 2비트는 명령어가 4바이트 정렬이라 항상 00
- 상위 4비트는 현재 PC에서 가져오므로, 같은 256MB 영역 안에서만 점프할 수 있다
- 더 멀리 가려면 주소를 레지스터에 넣고 `jr`(레지스터 주소 지정)를 쓴다

## 3. j, jr, jal의 차이

| 명령어 | 형식 | 동작 | 용도 |
| --- | --- | --- | --- |
| `j L` | J | PC ← L | 반복문, else 건너뛰기 |
| `jal L` | J | `$ra` ← PC + 4, PC ← L | 함수 호출 |
| `jr $rs` | R | PC ← `$rs` | 함수 복귀(`jr $ra`), switch 점프 테이블 |

- `jal`만 돌아올 주소를 저장한다. 그래서 함수 안에서 또 `jal`을 하려면 `$ra`를 스택에 저장해야 한다(과제 2 참고)

## 4. Hi, Lo 레지스터

32비트 × 32비트 곱셈 결과는 최대 **64비트**라 레지스터 하나에 다 들어가지 않는다.

| 연산 | Hi | Lo |
| --- | --- | --- |
| `mult $s0, $s1` | 곱의 상위 32비트 | 곱의 하위 32비트 |
| `div $s0, $s1` | **나머지** | **몫** |

- 결과는 `mfhi`, `mflo`로 일반 레지스터에 옮긴다
- 의사 명령어 `mul $d, $s, $t`는 `mult` + `mflo`라서 상위 32비트를 버린다(오버플로 검사 없음)

## 5. IEEE 754 단정밀도 변환

> **문제**: 2진수 −101.101101111010을 IEEE 754 단정밀도(32비트)로 표현하라.
{: .prompt-info }

단정밀도 형식은 부호 1비트, 지수 8비트(바이어스 127), 가수 23비트 순서다.

$$(-1)^S \times 1.\text{fraction} \times 2^{E - 127}$$

① 정규화: 소수점을 왼쪽으로 2칸 옮겨 1.xxx 꼴로 만든다

$$-101.101101111010_2 = -1.01101101111010_2 \times 2^2$$

② 부호 S = 1 (음수)

③ 지수 E = 2 + 127 = 129 = `10000001`

④ 가수: 맨 앞 1은 숨김 비트라 저장하지 않고, 소수점 아래 14비트 뒤를 0으로 채워 23비트

```text
S | E        | fraction
1 | 10000001 | 01101101111010000000000
= 1100 0000 1011 0110 1111 0100 0000 0000
= 0xC0B6F400
```

Python으로 `struct.pack('>f', -5.71728515625)`(10진수로 바꾼 값)을 확인하면 같은 비트가 나온다.

| 문제 | 10진수 | 비트 | 16진수 |
| --- | --- | --- | --- |
| −101.101101111010 (2024-2) | −5.71728515625 | 1 10000001 01101101111010000000000 | 0xC0B6F400 |
| −100.001110001 (2024 중간 다른 버전) | −4.220703125 | 1 10000001 00001110001000000000000 | 0xC0871000 |

> **(중요!!)** 지수는 2의 보수가 아니라 **바이어스 127**을 더해서 저장한다. 그래서 지수끼리 크기 비교가 정수 비교처럼 쉬워진다. 정규화한 1.xxx의 **1은 저장하지 않는다**.
{: .prompt-warning }

## 6. 32비트 상수 넣기: lui + ori

> **문제**: `$s0`에 `0000 0000 0011 1101 0000 1001 0000 0000`을 넣어라.
{: .prompt-info }

I 형식 상수는 16비트라 한 번에 넣을 수 없다. 상위 16비트와 하위 16비트로 나눈다.

| 부분 | 2진수 | 16진수 | 10진수 |
| --- | --- | --- | --- |
| 상위 16비트 | 0000 0000 0011 1101 | 0x003D | 61 |
| 하위 16비트 | 0000 1001 0000 0000 | 0x0900 | 2304 |

```assembly
lui  $s0, 61            # $s0 = 0x003D0000 (상위 16비트에 넣고 하위는 0)
ori  $s0, $s0, 2304     # $s0 = 0x003D0900
```

SPIM으로 `$s0`를 정수 출력하면 `4000000`이 나오고, 0x003D0900 = 4,000,000과 같다.

- 하위에 `addi`를 쓰면 안 되는 경우: 하위 16비트의 맨 앞 비트가 1이면 `addi`는 부호 확장을 해서 상위 비트가 바뀐다. `ori`는 0 확장이라 안전하다

## 7. 개선된 곱셈기 (Refined Version)

> **문제**: 0010 × 0011을 개선된 곱셈 하드웨어로 계산할 때 반복별 Product를 써라.
{: .prompt-info }

개선된 곱셈기는 곱하는 수(multiplier)를 Product 레지스터의 **오른쪽 절반**에 넣고 시작한다. 매 반복마다

1. Product의 최하위 비트가 1이면 왼쪽 절반에 Multiplicand를 더함
2. Product 전체를 오른쪽으로 1비트 시프트

| 반복 | 단계 | Multiplicand | Product |
| --- | --- | --- | --- |
| 0 | 초기값 | 0010 | 0000 0011 |
| 1 | LSB = 1 → 왼쪽 절반 + Mcand | 0010 | 0010 0011 |
| 1 | 오른쪽 시프트 | 0010 | 0001 0001 |
| 2 | LSB = 1 → 왼쪽 절반 + Mcand | 0010 | 0011 0001 |
| 2 | 오른쪽 시프트 | 0010 | 0001 1000 |
| 3 | LSB = 0 → 그대로 | 0010 | 0001 1000 |
| 3 | 오른쪽 시프트 | 0010 | 0000 1100 |
| 4 | LSB = 0 → 그대로 | 0010 | 0000 1100 |
| 4 | 오른쪽 시프트 | 0010 | **0000 0110** |

결과 0110 = 6 = 2 × 3. 위 표는 같은 과정을 Python으로 비트 연산해 출력한 값과 같다.

- 처음 버전과 비교: 64비트 Multiplicand 레지스터와 별도의 Multiplier 레지스터가 필요 없어 **하드웨어가 절반**이고, 덧셈기도 32비트면 된다

## 8. C를 MIPS로 바꾸기

### if-else

```c
if (i == j) f = g + h;
else        f = g - h;
```

f = `$s0`, g = `$s1`, h = `$s2`, i = `$s3`, j = `$s4`

```assembly
      bne  $s3, $s4, Else    # i != j 이면 Else로
      add  $s0, $s1, $s2     # f = g + h
      j    Exit              # else 부분 건너뛰기
Else: sub  $s0, $s1, $s2     # f = g - h
Exit:
```

- 조건을 **반대로**(`==` → `bne`) 써야 then 부분이 바로 아래에 온다
- `j Exit`를 빼먹으면 then을 실행한 뒤 else까지 실행된다

g = 7, h = 3으로 SPIM에서 실행하면 i = j = 5일 때 10, i = 5, j = 6일 때 4가 나왔다.

### 배열이 들어간 식

```c
f = -g + h + B[1];
```

f = `$s0`, g = `$s1`, h = `$s2`, B의 시작 주소 = `$s7`

```assembly
lw   $t0, 4($s7)       # B[1]: 인덱스 1 × 4바이트 = 4
sub  $s0, $s2, $s1     # h - g  (= -g + h)
add  $s0, $s0, $t0     # + B[1]
```

B = {10, 20, 30}, g = 7, h = 3이면 −7 + 3 + 20 = 16이고 SPIM 결과도 16이다.

- `sub $s0, $zero, $s1`로 −g를 먼저 만들어도 되지만, `h - g`로 묶으면 명령어가 하나 준다

## 최종 핵심 정리

1. 16비트 상수를 32비트로 늘릴 때 부호 비트를 복사해야 음수가 유지되고, 논리 연산 상수는 0으로 확장한다
2. 분기(`beq`, `bne`)는 PC 상대: (PC + 4) + 오프셋 × 4
3. `j`, `jal`은 의사 직접: PC 상위 4비트 + 26비트 주소 + 00, 그래서 같은 256MB 영역 안에서만 점프한다
4. `jal`만 `$ra`에 복귀 주소를 저장하고, `jr $ra`로 돌아온다
5. `mult`는 Hi(상위)·Lo(하위)에, `div`는 Hi(나머지)·Lo(몫)에 결과를 둔다
6. −101.101101111010₂ = −1.01101101111010 × 2² → S = 1, E = 129, 결과 0xC0B6F400
7. 32비트 상수는 `lui`(상위 16비트) + `ori`(하위 16비트), 0x003D0900은 `lui 61` + `ori 2304`
8. 개선된 곱셈기에서 0010 × 0011은 4번 반복 후 Product 0000 0110(= 6)
